## [0.1.0] - 2026-08-07

The first release: the complete v1 console. All six resource sections — agents, sessions, environments, credential vaults, skills, files — read and write against the platform's implemented surface; sessions stream their event trace live over SSE with human-in-the-loop tool approval; the agent editor carries both a rendered form and a raw JSON↔YAML tab; every platform call goes through the console's own server, so the management key never reaches the browser. Verified by 515 unit / 39 e2e / 5 live tests, a 28-surface Chrome fidelity manifest, and a probe ratchet. Every entry below landed pre-release and ships here.

- **Plan 05 approved — release management** (2026-08-07): the console has been feature-complete since plan 03 and verification-hardened since plan 04, and in that whole time it has never been released — `git tag -l` and `gh release list` both return nothing, `package.json` has said `0.1.0` since the scaffold commit and never moved, this changelog's only `##` heading is `Unreleased` (41 KB of it), and CI builds the Docker image only to gate it with trivy and throw it away, leaving clone-and-build as the sole path to a running console. [docs/plan/05_release-management.md](./docs/plan/05_release-management.md) scopes four slices: cut v0.1.0 by hand into the Keep-a-Changelog frame the platform repo already uses (its "Cut release 0.1.0 (#82)" is the precedent for the changelog and tag conventions; the automation and the published image are new ground this repo breaks first); publish a multi-arch GHCR image built **natively** on `ubuntu-latest` + `ubuntu-24.04-arm` — free for public repos, and emulating a Next.js build under QEMU is its own argument — scanned by the same trivy gate **before** anything is pushed; automate the cut with release-please; and show the running version in the sidebar. The tension named when the automation was chosen — release-please generates changelogs, this repo hand-writes a long-form narrative and CLAUDE.md says that narrative is written once — is dissolved rather than decided by the tool's `skip-changelog` option: release-please owns `package.json`, the tag, and the GitHub Release, and never touches `CHANGELOG.md`. Per release one human step remains, by design: `pnpm changelog:cut <version>` files the dated section, and the release workflow then replaces release-please's commit-derived release body with that section, so the GitHub Release reads as prose rather than as a list of PR titles. Two facts made decisions rather than preferences. `main`'s protection requires `ci-ok` + `docker` with `enforce_admins: true`, and the release-please action's own README states that "events triggered by the `GITHUB_TOKEN` will not create a new workflow run" — so a release PR opened with the default token would carry no checks and be **unmergeable by anyone, including an admin**. A credential is therefore a hard prerequisite, and it is a GitHub App rather than the five-minute fine-grained PAT: GitHub's default organization policy caps fine-grained PATs at **366 days**, and this repository lives in the `OpenSDLC-Dev` org, so a PAT would break the pipeline roughly a year out in the quietest possible way — the release PR simply stops appearing. An App mints a 1-hour token per run from a non-expiring key, attributes its actions to a bot instead of the maintainer, and installs onto the platform repo when the same automation goes there; the two are one workflow step apart, so the choice is reversible. Versioning is the console's own 0.x semver, independent of the platform (lockstep was declined: the console must be able to ship a fix without waiting for a platform release), with each release recording the platform version its live tier last ran green against — a stated compatibility fact, not an enforced handshake, since inventing a version handshake the platform does not serve would violate principle 1. Also declined, with reasons: letting release-please generate the changelog, a bot that pushes the changelog cut onto the release PR branch (workable, but it re-runs on every `synchronize`, must be idempotent, and races release-please's own branch regeneration — real complexity for one saved command), QEMU-emulated arm64, and CalVer. No `/api/version` endpoint: plan 04 decision 6 declined a `/verify` route because this console ships as a credentialed operator image where a route enumerating internal state is a liability, and a version string is a mild case of the same class — the sidebar already serves the operator who needs it. Two traps the review caught in the plan itself, both now written into slice 2: tag-push triggers do not fire retroactively, so the `v0.1.0` slice 1 pushes would never produce an image once the workflow lands a slice later (hence a `workflow_dispatch` path, dispatched once against the seed tag), and a GHCR package is **private on first publish** even when its repository is public — the OCI `source` label links it without making it anonymously pullable, so the unauthenticated `docker run` the README gains would 401 for every external reader until the package is flipped to public. Recorded as known gaps rather than fixed: nothing verifies the published image actually boots, there is no SBOM/provenance/signature tier, and the platform repo still publishes no image of its own.

- **Verification hardening, slice 3 — semantic state attributes replace formatted-text assertions** (2026-08-07, plan 04, issue #31): e2e asserted on rendered sentences — `"5,412 in · 890 out · 3,100 cache read"`, `"3s"`, `"5,412 / 890"` — so a copy edit or a locale change reddened the trace suite and said nothing about whether the trace worked. Derived state now carries its raw value in a `data-*` attribute and tests read that: the session usage chip and the sessions-list tokens cell (`data-input-tokens` / `data-output-tokens` / `data-cache-read-tokens`), the events toolbar (`data-tab`, `data-filter`, `data-visible-events`, `data-total-events`), model-span durations and idle bands (`data-duration-ms`, `data-idle-ms`), the pager (`data-has-prev` / `data-has-next`), and all five filter comboboxes (`data-value`). `data-state` on the stream badge and `data-event-type` on event rows were the existing precedent, not new invention. Event rows and the detail panel get their counters from one `usageAttrs` helper, absent when the event has no usage — so `[data-input-tokens]` selects exactly the rows that have one. **The attribute and the text can never disagree**: a `tokenAttr` sibling to `tokenCount` drops the attribute in precisely the cases the text shows a dash, because otherwise an overflowed counter would render `—` while the attribute read `Infinity` and a test would assert a number no operator can see. The convention is written down in CLAUDE.md beside the Chrome-fidelity rule, since the two divide one territory: attributes carry semantics, the fidelity pass owns appearance. **Measured, not asserted:** changing both number formatters (`tokenCount` → `` `${n} tok` ``, `durationLabel` → `` `${s} sec` ``) now reddens **1 e2e test and 2 unit tests** — one per formatter, each the designated owner of the formatter it names (`utils.test.ts` for `tokenCount`, `timing.test.ts` for `durationLabel`) — where before this slice's cleanup the same change reddened 9 unit tests across pages, rows and probes. The one e2e that fails is `token and duration formatting`, which exists to be that single point of contact. It pins the exact strings the console rendered before this slice (`5,412 in · 890 out · 3,100 cache read`, `3s`, `21:45:00`) and passes unchanged, which is also the evidence that nothing about the rendering moved: this slice adds attributes and changes no pixels, so no Chrome fidelity comparison applies. One scoping bug caught by the suite itself: the first attempt read the sessions-list cell with `.first()`, which is positional where the replaced assertion was content-addressed — the list sorts newest-first, so it matched the wrong session. Now scoped to its row. Review then found the convention broken by its own first implementation: the events toolbar reported `data-filter` and `data-visible-events` off state alone, so switching to Debug — which renders the log whole and hides the filter chips — left both attributes describing the transcript while seven rows were on screen, the precise contradiction the convention exists to forbid. Both are now read off the active tab, with `data-filter` **absent** in Debug on the same rule as `tokenAttr`: say nothing rather than something untrue. The regression test was confirmed red against the pre-fix render. Two consequences of taking the "one owner per formatter" rule literally: the missing-counter probe now asserts only the dash marker it owns and no longer the populated format, and `tokenCount` gained a unit-tier owner in `src/lib/utils.test.ts` — without it the format's only owner would have been an e2e test and `pnpm test` would have stayed green through a broken counter. That file also pins the `tokenCount`/`tokenAttr` pairing as a property across both branches, NaN and the wire-reachable `1e400` overflow included. 512 unit / 39 e2e green.

- **Verification hardening, slice 2 — the suite proves it can fail** (2026-08-07, plan 04, issue #31): a suite built only from passing assertions is loud in exactly the same way whether a surface works or has silently stopped being checked. This slice adds the assertions that can tell the difference, and the first one it wrote **found a real bug**. `src/app/(console)/sessions/[id]/page.tsx` read `session.usage.input_tokens.toLocaleString()` unguarded, so a session whose `usage` was missing one counter took down the whole page with `TypeError: Cannot read properties of undefined` — the operator's only view of a running session, lost to one absent integer. The **sessions list had the identical unguarded read** (`s.usage.input_tokens.toLocaleString()`), so one broken row took the whole table down — found by extending the same probe to the list, and verified by reverting the fix and watching it throw. Both now share a `tokenCount` helper that degrades to an honest `—` per counter, matching `summary.ts`'s `tokensLine` and plan 03's null-safe time math: say what is known, never guess the rest. A second asymmetry surfaced at the trace seam: `applyFrame` dropped events without a string `id` but `applyPersisted` admitted them, so identical malformed input behaved differently depending on whether it arrived by stream or by reseed — and because `seen` keys on id, two id-less events deduped into one, silently rendering one event where the wire sent two. Both doors now apply the same guard. **The canary** ([schemas.test.ts](./src/lib/platform/schemas.test.ts)): five inline fixtures that violate a schema in one field each — a counter as a string, a dropped required field, an enum value the platform rejects, a reserved seam carrying a value, a union arm missing its member — asserted to **fail**, plus a check that each one's base fixture still conforms, so a red canary means the gate broke rather than the fixture rotting. Neutering `SessionSchema` to a loose object leaves all 20 fixture assertions green and turns two canaries red with "the conformance gate is not doing anything" — which is the whole point, since passing assertions alone cannot detect a disabled gate. **Contract-violation probes** at the two seams adversarial input actually reaches ([store.violations.test.ts](./src/lib/session-trace/store.violations.test.ts)): id-less events from either door, two id-less events not collapsing into one, a `content_delta` whose event never persists (the preview stays and does not block the log), out-of-order delta indices, a duplicated batch replayed after reconnect, a corrupted replay not rewriting settled history, and near-miss frame types not marking a trace deleted. **A ratchet** (`pnpm probes:check` → [scripts/check-probes.mjs](./scripts/check-probes.mjs), a CI step) names those seams and fails with an actionable message if any module loses its probe coverage. It asks Vitest for the tests it actually **collects** rather than grepping source, because source text is not evidence that anything runs (review finding, PR #35): a commented-out block, an `it.skip`, and a `describe("probe: …")` whose children were deleted all vanish from collection, while a regex over the file would have counted all four — a ratchet satisfiable by dead text being precisely the failure this slice exists to prevent. Verified both ways: deleting the probes reddens it, and so does `describe.skip`-ing them while every `probe:` string stays in the file. Per decision 7 the rule applies where adversarial input arrives, not across all 60 test files; adversarial tests are marked by a `probe:` name prefix, and existing ones in `timing`/`summary` were relabeled to the convention. 508 unit (was 490; the meta-test moved to a script) / 38 e2e green; coverage 99.7% lines. A review pass caught one more reachable case in the same helper: JSON has no `NaN` literal but does parse `1e400` to `Infinity`, which `toLocaleString` renders as `∞` — the counter guard now requires finiteness, with its own probe. Also fixed: `coverage/` is now eslint-ignored, so running `pnpm test:coverage` before `pnpm lint` locally no longer fails the gate on generated reporter assets (CI lints first, so it never saw this).

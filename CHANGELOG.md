## Unreleased

- **Verification hardening, slice 2 — the suite proves it can fail** (2026-08-07, plan 04, issue #31): a suite built only from passing assertions is loud in exactly the same way whether a surface works or has silently stopped being checked. This slice adds the assertions that can tell the difference, and the first one it wrote **found a real bug**. `src/app/(console)/sessions/[id]/page.tsx` read `session.usage.input_tokens.toLocaleString()` unguarded, so a session whose `usage` was missing one counter took down the whole page with `TypeError: Cannot read properties of undefined` — the operator's only view of a running session, lost to one absent integer. The chip now degrades to an honest `—` per counter, matching `summary.ts`'s `tokensLine` and plan 03's null-safe time math: say what is known, never guess the rest. A second asymmetry surfaced at the trace seam: `applyFrame` dropped events without a string `id` but `applyPersisted` admitted them, so identical malformed input behaved differently depending on whether it arrived by stream or by reseed — and because `seen` keys on id, two id-less events deduped into one, silently rendering one event where the wire sent two. Both doors now apply the same guard. **The canary** ([schemas.test.ts](./src/lib/platform/schemas.test.ts)): five inline fixtures that violate a schema in one field each — a counter as a string, a dropped required field, an enum value the platform rejects, a reserved seam carrying a value, a union arm missing its member — asserted to **fail**, plus a check that each one's base fixture still conforms, so a red canary means the gate broke rather than the fixture rotting. Neutering `SessionSchema` to a loose object leaves all 20 fixture assertions green and turns two canaries red with "the conformance gate is not doing anything" — which is the whole point, since passing assertions alone cannot detect a disabled gate. **Contract-violation probes** at the two seams adversarial input actually reaches ([store.violations.test.ts](./src/lib/session-trace/store.violations.test.ts)): id-less events from either door, two id-less events not collapsing into one, a `content_delta` whose event never persists (the preview stays and does not block the log), out-of-order delta indices, a duplicated batch replayed after reconnect, a corrupted replay not rewriting settled history, and near-miss frame types not marking a trace deleted. **A meta-test ratchet** ([adversarial-probes.test.ts](./src/lib/adversarial-probes.test.ts)) names those seams and fails with an actionable message if any module loses its probe coverage — verified by deleting the probes and watching it redden. Per decision 7 the rule applies where adversarial input arrives, not across all 60 test files; adversarial tests are marked by a `probe:` name prefix, and existing ones in `timing`/`summary` were relabeled to the convention. 516 unit (was 490) / 38 e2e green; coverage 99.7% lines. A review pass caught one more reachable case in the same helper: JSON has no `NaN` literal but does parse `1e400` to `Infinity`, which `toLocaleString` renders as `∞` — the counter guard now requires finiteness, with its own probe. Also fixed: `coverage/` is now eslint-ignored, so running `pnpm test:coverage` before `pnpm lint` locally no longer fails the gate on generated reporter assets (CI lints first, so it never saw this).

- **Verification hardening, slice 1 — the wire schemas become the source of truth** (2026-08-07, plan 04, issue #31): [src/lib/platform/schemas.ts](./src/lib/platform/schemas.ts) now holds the platform's rendered wire shapes as zod schemas carrying the `internal/api/*.go` / `internal/domain/*.go` file:line cites, and [types.ts](./src/lib/platform/types.ts) is reduced to `export type … from "./schemas"` — one transcription instead of two, with the same 22 types. All 42 consumers compile untouched and the 476-test suite is unchanged, which is the evidence that the inferred types are structurally identical to the hand-written ones. zod is a **devDependency** that never reaches a bundle: the re-export is erased whole at compile time, and an eslint `no-restricted-imports` pair pins it — nothing outside `src/lib/platform/` may import zod or the schema module, and inside it only `schemas.ts` and its test may. Both arms were verified by probe imports that failed as intended. **Link A** ([schemas.test.ts](./src/lib/platform/schemas.test.ts), 14 tests in CI) validates everything the mock serves: every collection `fixtures.mjs` exports — a file `tsconfig` doesn't typecheck at all — including the `agentVersions` / `sessionEvents` / `vaultCredentials` / `skillVersions` maps, plus the responses `server.mjs` _constructs_ on the write paths, which no fixture covers (review finding, PR #32). The mock now exports its server behind a run-as-main guard so the suite can drive it on an ephemeral port; a completeness assertion fails if a new fixture collection is added without being validated. Corrupting one fixture field reports `sessions[0] … path: ["usage","input_tokens"] — Invalid input: expected number, received string`. **Link B** ([test/e2e-live/live.spec.ts](./test/e2e-live/live.spec.ts)) parses _real_ platform responses through the same schemas at the two existing helpers, plus the real event trace the HITL test already copies — the failure link A cannot catch, since fixtures and transcription can stay mutually consistent while both drift. Routes the live suite never calls say so out loud rather than passing quietly; run against the real compose stack it stayed **5/5 with zero shape mismatches**, which is the fact the audit alone could not establish — the schemas were checked against the platform's source, and now against what a running platform renders. **The reference-wire audit** ran in full against `@anthropic-ai/sdk` 0.115.0 and landed as [docs/wire-divergences.md](./docs/wire-divergences.md): **zero transcription bugs** across 22 shapes and 10 enum narrowings; every difference is the reference being looser than the platform renders, except `SessionEvent.processed_at`, where the reference declares non-null and the platform serves null on echoed inbound events — the one row where adopting the SDK would have deleted the null-safe trace timing plan 03 built, and the whole argument for principle 1. Nothing landed in `package.json`. Plan decision 2 was **amended on evidence**: it specified `z.looseObject`, but probing zod 4.4.3 showed plain `z.object` already strips unknown keys rather than rejecting them (only `z.strictObject` rejects), while `looseObject`'s inferred type carries `[k: string]: unknown` — which, now that the types infer from the schemas, would have silently deleted typo protection on every shape. `looseObject` is kept for `SessionEvent` and `ContentBlock`, the two whose transcription genuinely has an index signature.

Two links, two tiers: fixtures ↔ schemas runs in CI, schemas ↔ the real platform runs in the live tier. Anthropic's official TypeScript SDK turned out to publish generated types for this exact resource surface and no runtime schemas — so it can't supply the validator, but it gives the hand transcription a reference to diff against for the first time, and the platform's own wire structs already cite those type names (`internal/api/agents.go:15`: "agentJSON is the BetaManagedAgentsAgent wire shape"). The audit reads a checkout rather than adding a dependency — nothing lands in `package.json`, and principle 1 keeps the reference product from ever defining our shapes. Declined with reasons: the sample's VerifiableUnit/registry/runner framework, `/verify` routes in the credentialed product build, runtime prop schemas, browser-side response validation, and the replay recorder. Recorded as a known gap, not fixed: principle 3's feature detection is stated but unimplemented — every 404 renders as `ErrorState`, so "the platform lacks this capability" and "this resource does not exist" are indistinguishable.
